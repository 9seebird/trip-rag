## 한 줄 요약

한국관광공사 관광정보(TourAPI)를 벡터 검색으로 다뤄서, **"비 오는 날 애기랑 갈 만한 제주 실내"** 같은
말로 장소를 찾고, 고른 곳 근처로 **반나절 코스**를 짜주는 서비스. 이직용 포트폴리오.

| 항목 | 결정 |
|---|---|

| 백엔드 | FastAPI + Docker Compose |
| 화면 | 정적 HTML을 서버가 직접 서빙 (라포엠 데모와 같은 방식) |

| 속도 | **빠르게 진행 희망.** 압축 일정 4일 / 약 20시간 |

## 다음에 할 일 (순서대로)

1. **폴더 만들고 Cowork에 연결** ← 이것부터
2. `docker-compose.yml` + `sql/init.sql` (pgvector 포함 스키마)
3. **수집 스크립트** — 목록 받기 / 상세 이어서 받기
   - 상세 조회는 건당 1회, 하루 1,000회 제한 → `detail_status`로 진행 상태를 DB에 기록하고
     끊겨도 이어서 도는 구조로. 첫날 밤에 걸어두면 다음 날 데이터가 쌓여 있음
4. 청킹 + 임베딩 + pgvector 인덱스
5. 벡터 검색 API → 조건 필터 → 리랭커
6. 화면 (검색 / **비교 보기** / 코스)
7. 평가 20문항 + 실험 표
8. 배포

세부 내용은 `설계문서.md` 참고. 특히 7장(평가)과 12장(함정)은 꼭 읽고 시작할 것.

## 이 프로젝트에서 절대 빠뜨리면 안 되는 것

**평가.** 질문 20~40개와 정답 장소를 짝지어 두고 recall@k를 재는 스크립트.
그리고 "뭘 바꿨더니 얼마나 좋아졌나" 표. 이게 없으면 흔한 RAG 데모가 됩니다.
특히 **임베딩 모델 비교**와 **리랭커 전후 비교** 두 줄이 이 포트폴리오의 핵심입니다.

**비교 보기 화면.** 같은 질문에 키워드 검색과 의미 검색 결과를 나란히 놓는 화면.
"비 오는 날"로 검색했을 때 한쪽은 비고 한쪽은 박물관·아쿠아리움이 뜨는 그림 하나가
이 프로젝트 전체를 설명합니다.

**운영 이야기.** 비용(비즈라우터 `usage.cost`로 원화 확인 가능), 갱신 주기, 응답 속도.
인프라·운영 경험이 강점이므로 여기서 차별점이 납니다.
